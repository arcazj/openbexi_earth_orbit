# Release Notes

## Version 2.2.1 Development Patch (2026-08-29)

Version 2.2.1 adds explicit, opt-in server-managed daily data maintenance. `npm run serve:update` binds the loopback server first, then keeps GP/OMM, compatibility TLE, SATCAT, launch, confirmed-decay, and complete-active reconciliation work on independent 24-hour clocks until graceful shutdown. `npm run serve` remains offline by default, and static hosts such as GitHub Pages cannot execute the scheduler.

Normal orbital cycles perform non-pruning newest-epoch upserts; pruning is limited to a separately due reconciliation that accepts only a structurally valid, quarantine-free, complete `active` response. One SATCAT fetch feeds both history-retaining launch and confirmed-decay catalogs. Conditional or byte-identical responses avoid data and backup churn, while partial failures preserve last-known-good artifacts. The scheduler adds bounded retry with jitter, stale-lock recovery, nonblocking post-bind startup, graceful worker shutdown, and detailed `/api/data-update-status` lifecycle, interval, revision, retry, and reconciliation diagnostics.

The final updater hardening rejects a production-scale full replacement or reconciliation when an established GP, TLE, or SATCAT catalog has at least 1,000 records unless the candidate record count and canonical NORAD overlap each retain at least 75% of the last-known-good catalog. `--force` cannot bypass the guard. Only direct `export-gp`, `export-tle`, and `refresh-satcat` operations may use the explicit `--allow-large-catalog-shrink` recovery override; `maybe-update` and server-managed maintenance cannot. Changed artifacts receive collision-safe backups with the newest seven retained per artifact. An accepted `304` revalidation resets the daily due age without changing catalog bytes or revisions.

GP, TLE, SATCAT, launch, and decay errors persist in their metadata and are reconstructed after restart. The public status API reports all five histories and recursively sanitizes bounded error text throughout nested cycle results, including credential-like assignments, bearer values, URL user information, and control characters.

Final local Version 2.2.1 development verification passed 56 of 56 JavaScript cases and 89 of 89 Python cases. The 27-declaration Playwright matrix completed in 5.6 minutes with 18 passes and 9 intentional project/profile skips, and the frozen static build contains 122 files totaling 205,788,178 bytes. The final validation inventory contains 124 hashed artifacts and 46 named evidence records, including the byte-exact CRLF SATCAT no-churn regression. These local results do not constitute candidate, validated, or operational evidence.

The bundled GP/OMM, compatibility TLE, SATCAT, launch, and confirmed-decay artifacts completed reconciliation on 2026-08-29/30 UTC. A later compatibility TLE retry returned HTTP 503, so its successful 2026-08-30 snapshot and revision were preserved while the retry failure remained visible in metadata. Repository-owner confirmation dated 2026-08-29 records data-owner approval to redistribute these exact bundled-source bytes through repository-root GitHub Pages; later provider refreshes require renewed review. Compatibility TLE support decodes numeric and explicit Alpha-5 identifiers to canonical strings, but remains an incomplete subset of current six-digit GP/OMM coverage. Version 2.2.1 remains **Experimental**, **non-operational**, and in **development** publication state with null candidate and release dates; this patch does not close the open promotion, independent-review, completeness, rollback-rehearsal, or operational gates.

## Version 2.2.0 Development (Not a Release Candidate)

Version 2.2 development restores catalog continuity beyond the five-digit TLE identifier boundary. CelesTrak GP OMM JSON becomes the preferred orbital-element source, complete NORAD identifiers remain strings, and the mixed catalog initializes OMM through satellite.js `json2satrec` while retaining legacy TLE through `twoline2satrec`. The new `export-gp`, `json/gp/GP.json`, and `/api/gp` contracts are primary, `/api/gp-metadata` exposes the generated GP sidecar unchanged, and `/api/satellites` returns preferred GP with legacy fallback. `export-tle`, `json/tle/TLE.json`, and `/api/tle` remain deprecated compatibility paths for this development release. OMM is never converted to synthetic TLE, and invalid or unsupported records are quarantined independently.

The generator derives orbit class consistently from numeric mean-element metrics for both GP and compatibility TLE output, correcting navigation-constellation records into `MEO`. It enriches GP group/tag values through an exact full-string NORAD join to the one-release TLE compatibility catalog and records the compatibility-catalog revision, deterministic tag-map revision, and match counts in GP metadata; this enrichment never supplies orbital state or weakens six-digit identity. Category-colliding source tags retain their raw filter/share keys but use qualified UI labels, including `Geosynchronous group` for the raw `GEO` tag, so a dependent tag cannot be mistaken for an active orbit category. Default preferred GP and incremental TLE compatibility maintenance each issue one request for the CelesTrak `active` group. The overlapping `last-30-days` request was removed after its endpoint returned HTTP 404; explicit `export-tle --all` retains the historical multi-group workflow.

Launch events are generated from SATCAT independently of propagatable orbit records, so post-2026-07-11 launches and details-only objects can remain visible. Confirmed decay data remains a separate governed dataset. GP, launch, and decay freshness are scheduled independently, including launch and decay work in the same due cycle. Launch and re-entry timelines replace stale caches when the composite `data_revision` changes, deduplicate events, and keep confirmed-over-predicted decay precedence. Data health publishes that composite plus the compatibility GP-only `catalog_revision` and per-dataset revisions, along with retrieval/newest-event dates, format/identifier/quarantine counts, and last error. With GP metadata absent, its TLE fallback state requires a packaged TLE file larger than the empty `[]` sentinel and otherwise becomes unavailable; that fallback is artifact availability, not validation. GP metadata instead follows normal current/partial/degraded evaluation, and failed or partial updates retain last-known-good artifacts without reporting successful completion.

Without an explicit API base, static pages poll only same-origin packaged metadata and refresh changed packaged catalogs and both timelines in the same document. Explicit API configuration selects the separately operated server path; the browser never fetches provider data directly. The durable registry freezes content-addressed catalog, metadata, and revision files while recording distinct acquisitions append-only, and validates malformed/non-propagatable GP before reduced-coverage TLE bootstrap. Python-backed npm commands share one Python 3 discovery path with an `OPENBEXI_PYTHON_COMMAND` override.

The Version 2.2 browser follow-up replaces separate orbit/debris behavior with one union-capable `ALL`/`GEO`/`MEO`/`LEO`/`HRO`/`Debris`/`Others` category control and makes `MEO` the fresh-page-load default. The visible `HRO` label maps to the domain `HEO` value; debris and rocket bodies take category precedence without overriding an authoritative non-debris object type. Changing filters to exclude the selected object clears that selection and its show-only/detail state. Selected GP metadata and TLE/OMM elements now have one de-duplicated right-side details surface, while obsolete duplicate menu details are removed. Combined Globe plus Mercator mode keeps the map clickable above timeline/detail visualization layers, while fixed `Time x` and server controls remain usable above Mercator-only fullscreen.

One signed simulation clock now advances every time-dependent browser layer once per animation frame: each `Time x` unit is one simulation minute per real second, negative values reverse, zero pauses, rates are limited to `-60..60`, and applied frame gaps are capped at `0.25 s`. This removes the duplicate Solar System accumulator. The selected satellite uses an exact SGP4 state at each simulation frame; other visible satellites use Hermite interpolation between asynchronously sampled states with orbit-period-fraction window caps, discard stale jobs after direction or catalog changes, and preserve mesh/material identity. High warp that exceeds the bounded catalog cadence is reported while the selected satellite remains exact. The interpolation is display-only and does not enter conjunction calculations. In Solar System mode, the clock clamps and pauses at the bundled JPL-derived ephemeris boundaries instead of extrapolating, exposes that boundary in the UI, and permits inward reverse motion.

Catalog materialization prioritizes the fresh-page-default `MEO` population and publishes its first chunk before the remainder completes. Each accepted record keeps a stable `Object3D` state/selection proxy, while one batched `THREE.Points` layer renders current-epoch-ready Globe markers. Up to 1,000 drawn markers retain the local icon texture; denser views use compact per-marker colors. Replaced point geometry/material is disposed, and the source texture/material is disposed only when loader-owned rather than injected/shared. New filter-eligible proxies stay absent from that layer until the shared motion pass commits a finite position for the current simulation epoch, avoiding transient origin markers and old samples after paused time jumps. Rate/selection/job changes preserve usable in-window interpolation while superseded work is discarded. Mercator markers reuse those same exact-selected/interpolated-catalog positions instead of running a duplicate catalog propagation pass. Above 1,000 drawable records Mercator uses one compact density path plus the detailed selected marker, skipping per-object icon draws, sorting, and non-selected labels. Its redraw adapts to visible count and the selected ground track is cached under bounded simulation/real-time refresh rules; a failed same-satellite rebuild clears the stale path and caches the failed instant instead of retrying on every redraw. Failed selected or catalog propagation hides the affected marker/model current-position geometry, retries on a bounded backoff, and restores only after finite recovery, including corrected selected propagation at the unchanged simulation instant without animation frames postponing the retry deadline. A failed selected-orbit resample instead retains the last finite path; successful resampling refreshes its existing geometry in place at a bounded running cadence. Full-catalog search remains in the visible typeahead while the hidden compatibility selector is virtualized to `None` plus the active NORAD. The byte-identical obsolete `obj/loral.glb` copy is removed; canonical `obj/SSL_1300.glb` remains unchanged and mapped only to its intended satellites.

Version 2.2 is **Experimental**, **non-operational**, and in **development** publication state with no candidate or release date. The development authorization covers the GP/OMM, lifecycle-event, compatibility, cache/revision, API, packaging, browser filtering/details/layering, bounded time/motion correctness, documentation, and regression scope tracked for Version 2.2. Passing local tests does not close the open v2.0/v2.1 gates, approve public redistribution, prove complete authoritative coverage, or authorize collision probability, CDM/covariance analysis, operational risk scoring, alerts, reports, or maneuver recommendations.

## Version 2.1.0 Development (Not a Release Candidate)

Version 2.1 development adds an optional authenticated, single-node full-catalog close-approach service. It freezes catalog revisions into private content-addressed storage, registers startup and successful scheduled TLE revisions, reconciles new/changed/reappeared observations, and permits `ABSENT` only after a successful explicit full-source snapshot. The current incremental source is `PARTIAL` and cannot infer absence. The service persists bounded jobs and event revisions in SQLite, executes screening in an isolated Node subprocess, and exposes versioned `/api/v1` health, catalog, job, replay, cancellation, SSE progress, and paginated event routes. Catalog responses omit private artifact paths, while capabilities expose normalized defaults and structured request limits. The browser adds a server-capability workspace with a page-memory bearer token, explicit Experimental/non-operational/Pc-unavailable labels, partial-coverage counts, and polling fallback; static hosting retains the Version 2.0 selected-object workflow.

The broad phase partitions time into slabs and uses bounded swept spatial hashing before synchronized TCA refinement. Multi-format contracts cover TLE JSON, CCSDS OMM JSON/KVN, CCSDS OEM KVN, and provider ephemeris JSON with strict provenance, frame, UTC, unit, size, and interpolation rules. Only the bundled TLE snapshot is registered automatically; implementing adapters does not admit a provider feed or resolve licensing.

Initial development evidence includes brute-force candidate-recall oracles on tractable deterministic catalogs, a direct-engine 16,443-object 60-second observation, and a separate real loopback HTTP/store/worker run. The engine run completed in about 2.97 seconds and returned `PARTIAL`, with 1,492,127 pair intervals explicitly unscreened. The end-to-end worker completed in about 4.39 seconds and also correctly returned `PARTIAL`; the registered source was `PARTIAL` with `PARTIAL_SOURCE_DATASET`, and bounded persistence reduced the run to 22 progress rows and 26 total outbox rows with a 38.1 MB post-shutdown runtime. Consumer acknowledgement/pruning, retention automation, and representative storage budgets remain open. These are single-machine development observations, not portable performance or accuracy claims.

Version 2.1 remains Experimental, non-operational, and was never promoted to a candidate or release. It does not provide collision probability, CDM/covariance analysis, operational risk scoring, reports, alerts, or maneuver recommendations. Open v2.0 and v2.1 promotion gates remain open. A later, separate authorization assigned Version 2.2 to GP/OMM catalog continuity; it did not authorize those deferred collision-likelihood or operational capabilities.

## Version 2.0.0 Preview Candidate

The Version 2.0.0 candidate adds strict orbital-data contracts and Experimental selected-object close-approach screening in a module Web Worker. Results include time of closest approach, geometric miss distance, relative speed, data and algorithm provenance, quality flags, and synchronized 3D playback.

This preview is non-operational. Collision probability remains unavailable because the current TLE catalog does not provide validated covariance and hard-body-radius inputs. The feature does not provide operational alerts, maneuver advice, or a complete catalog guarantee.

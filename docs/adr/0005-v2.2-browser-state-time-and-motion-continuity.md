# ADR 0005: Browser State, Time, and Motion Continuity in v2.2

- Status: Accepted for Version 2.2 development
- Date: 2026-08-23
- Decision owners: project maintainers

## Context

The browser accumulated several overlapping presentation paths: orbit and debris controls could represent inconsistent selections, selected GP/TLE metadata appeared in more than one surface, Mercator could fall behind other layers, Solar System motion had a separate time accumulator, and catalog sprites advanced in staggered propagation steps. Those differences made a single shared view difficult to reproduce and created visible jumps or contradictory state without improving the scientific calculation.

The bundled Solar System ephemeris is finite. Treating dates beyond its table as if they remained JPL-derived would be an unsupported extrapolation. At the same time, visual smoothing of satellite state proxies and batched markers must not become an implicit propagation or screening model.

## Decision

Version 2.2 uses one browser-state and time boundary:

1. The orbit/object category vocabulary is `GEO`, `MEO`, `LEO`, `HEO`, `DEBRIS`, and `OTHER`; `ALL` is their union. The visible `HRO` label maps to domain `HEO`. A fresh page load starts with `MEO`, while explicit valid shared state takes precedence.
2. Specific category buttons form a union. Choosing one while `ALL` is active makes it exclusive; deselecting the final specific category restores `ALL`. Menu state, marker visibility, count, search, tag intersection, and shared-link serialization consume the same normalized selection. A filter change that excludes the selected object clears selection, selected-model/detail state, and show-only mode coherently. Visible typeahead owns catalog discovery; the hidden compatibility `<select>` retains only `None` and the active full-string NORAD rather than one option per record.
3. Authoritative debris/rocket-body/stage object type takes precedence over orbit class. An authoritative non-debris type takes precedence over debris-like name text; heuristics apply only when type is missing or unknown. Unknown orbit classes remain visible under `OTHER`.
4. One right-side selected-satellite panel owns de-duplicated satellite and GP element details. It renders either canonical OMM scalar fields or the two legacy TLE lines once, with optional model-source attribution. The duplicate menu metadata/TLE surface is removed.
5. Combined Globe plus Mercator mode keeps the map clickable above timeline and selected-detail visualization layers. Mercator-only fullscreen keeps the fixed `Time x` and server controls visible and usable above the map. Mercator reuses exact selected/interpolated catalog positions from the shared motion pass, adapts redraw cadence to visible count, caps non-selected labels, and caches the selected track under bounded simulated/real-time refresh rules. A failed same-satellite rebuild clears the old path and records the attempted simulation instant, preventing stale display and per-redraw retry at that unchanged instant.
6. `js/simulationClock.js` owns the visualization UTC instant and signed `Time x` rate. One rate unit advances one simulation minute per real second; negative values reverse, zero pauses, and input is clamped to `-60..60`. It advances once per animation frame, caps the applied frame gap at `0.25 s`, and supplies the reused `SIM_DATE` to every time-dependent layer. A second Solar System accumulator is prohibited.
7. Catalog setup processes fresh-page-default `MEO` records first and may publish the first MEO-bearing chunk before the remainder. Each accepted record owns a stable `Object3D` state/selection proxy; one batched `THREE.Points` layer renders only proxies that are both filter-eligible and current-epoch render-ready. Up to 1,000 drawn markers use the local icon texture, while denser views use compact per-marker colors. Catalog replacement disposes the replaced point geometry/material and disposes the source material/texture only when the loader marked it application-owned; injected/shared sources remain caller-owned. A proxy is not render-ready until the shared motion pass commits a finite position whose exact selected instant or interpolation window covers the current simulation UTC, so construction and out-of-epoch filter re-admission cannot show origin or old-position geometry. The selected satellite then uses an exact SGP4 state at each simulation frame. Other filter-visible satellites may use cubic Hermite scene interpolation between asynchronously sampled SGP4 states, with each window capped to a configured fraction of that orbit's period. Catalog replacement or discontinuous time invalidates stale state; selection, rate-direction, and sampling-job changes supersede pending work without hiding an otherwise valid in-window interpolation. Invalid propagation hides the marker/model, records explicit invalid state, and retries after a bounded delay; repeated animation frames do not postpone the selected retry deadline, and a finite retry at the same simulation UTC restores visibility only under the current filter. The selected one-revolution orbit retains its root/material and refreshes path geometry in place at a bounded simulated and real-time cadence. If high warp requires a larger window, catalog-marker cadence is explicitly reported as limited while selected orientation and footprint rendering reuse the exact selected state.
8. The local JPL-derived Solar System table supplies finite clock bounds while Solar System mode is active. Reaching an edge clamps to the exact boundary sample, pauses, and reports the condition. An inward signed rate resumes. Missing or invalid data may use the labeled analytical fallback; valid table data is never extrapolated.
9. Hermite positions are display artifacts only. Conjunction Workers, the durable runner, exports, element-age checks, and provenance use explicit UTC and supported raw propagation states.

## Consequences

- Filtered counts, search, rendering, and shared links have one category source of truth.
- Full-catalog search does not require thousands of hidden DOM `<option>` nodes.
- The default view is intentionally narrower (`MEO`) while `ALL` remains one action away; changing the filter to exclude the selected object clears the dependent selection state.
- The default MEO view can become useful before full catalog materialization, without showing unpropagated markers at the origin. The batched Globe layer avoids one rendered sprite/material per record; dense Mercator views replace per-object icons/sorting/labels with one compact path while retaining a detailed selected marker. Visible catalog motion is smoother without allocating replacement render objects per frame, Mercator does not duplicate catalog propagation, and selected-orbit refresh avoids root/material churn. Asynchronous sampling and map/track drawing still consume bounded browser CPU and can be partial when propagation fails.
- A background tab does not replay its entire missed wall-clock interval because the frame delta is capped.
- Solar System time cannot pass the authoritative ephemeris range until the mode is exited or the direction is reversed inward.
- Screening behavior, collision-probability availability, scientific maturity, and operational classification do not change.

## Verification and Cleanup

Unit tests cover category normalization/precedence, MEO-first chunk ordering, current-epoch hidden-until-finite marker readiness and filter re-admission, batched point-layer membership/density/selection behavior, hidden-selector virtualization, signed clock bounds, Hermite interpolation, job supersession with valid-state preservation, exact selected state, propagation failure/retry/recovery at an unchanged simulation instant, shared-position Mercator rendering, detailed-to-density map transition, adaptive map/label/track budgets, failed-track clearing/suppression, bounded in-place orbit refresh, and ephemeris clamping. Checksum-bound source evidence covers ownership-aware point-layer disposal. Browser tests must cover fresh `MEO`, share restore, point-layer filtering and catalog replacement, no origin markers during partial startup, Mercator interaction/layering/density mode, consolidated details, smooth forward/reverse selected motion, stable object identity, no catalog refetch on time changes, and visible ephemeris boundary pause. Static packaging must include the category, clock, interpolation, and ephemeris files without adding an external request, and must omit the removed byte-identical `loral.glb` duplicate.

Obsolete duplicate menu details, separate debris controls, the integrated duplicate Solar System accumulator, and staggered visible-sprite snapping are removed. Compatibility parsing for older shared debris links remains bounded and tested.

## Scope Boundary

This decision is browser visualization correctness for a Version 2.2 development build. It does not authorize a candidate/release, public redistribution, collision probability, covariance/CDM processing, alerts, reports, operational use, or maneuver recommendations. Final evidence hashes, performance measurements, and checklist closure are recorded only after runtime and tests are frozen.

## Rollback

Restore a complete previously checksummed application artifact with its matching static manifest; do not combine an older `index.html` with newer category/clock/motion modules. Data rollback remains governed by ADR 0004 and `docs/engineering/ROLLBACK_V2_2.md`. A rollback must retain visible reduced-coverage labeling for TLE fallback and must not reinterpret interpolated scene state as scientific output.
